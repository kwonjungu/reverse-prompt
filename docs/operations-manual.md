# 운영 매뉴얼 — 무엇을 해 두면 되는가

이 문서는 운영자(연구 책임자)가 **직접 해야 하는 일**만 순서대로 적는다. 코드 설명은 `CLAUDE.md`에 있다.

---

## 1. 처음 한 번 — 배포 설정 (약 10분)

### 1-1. 어느 Firebase 프로젝트인지 확인
- Vercel → 프로젝트 → **Settings → Environment Variables** → `NEXT_PUBLIC_FIREBASE_PROJECT_ID` 값을 눌러 본다.
- 이 값이 앱이 쓰는 Firebase 프로젝트다. 아래 모든 Firebase 작업은 **이 프로젝트**에서 한다.
- 저장소에는 두 이름(`.firebaserc`의 `promptgrader-jun`, 문서 링크의 `promptgrader`)이 섞여 있으니 이 값으로 판단한다.

### 1-2. 서버 키 넣기 (`FIREBASE_SERVICE_ACCOUNT_JSON`) — 꼭 필요
1. Firebase 콘솔 → 1-1의 프로젝트 → 톱니바퀴 **프로젝트 설정 → 서비스 계정 → 새 비공개 키 생성**.
2. 받은 `.json` 파일을 메모장으로 열어 **전체 복사**.
3. Vercel Environment Variables → **Add** → Key `FIREBASE_SERVICE_ACCOUNT_JSON`, Value에 붙여 넣기, **Production** 체크(미리보기에서도 쓰려면 Preview도), 가능하면 **Sensitive** 켜기 → Save.
4. 받은 파일은 지우거나 안전한 곳에 둔다. 채팅·GitHub에 올리지 않는다.

> `STUDENT_SESSION_SECRET`은 이제 넣지 않아도 된다. 비어 있으면 이 서버 키에서 자동으로 만든다.
> 나중에 서버 키를 새로 바꾸면 들어와 있던 학생·관리자 로그인이 한 번 끊긴다.

### 1-3. 관리자 비밀번호 (`ADMIN_PASSWORD`)
- 이미 넣었다면 그대로 둔다. 10자 이상이어야 한다.

### 1-4. 배포
- `claude/wizardly-bell-klkk3y` 브랜치를 `main`에 합친다(요청하면 PR을 만들어 준다). 1~2분 뒤 Vercel Deployments 맨 위가 **Ready**.

### 1-5. 배포 확인
1. `사이트주소/admin` 접속 → 빨간 **"서버 설정이 필요합니다"** 상자가 없으면 서버 설정 완료.
2. `ADMIN_PASSWORD`로 로그인.
3. 빨간 **"Firebase Authentication이 아직 시작되지 않았습니다"**가 보이면 상자의 링크로 Firebase 콘솔에 가서
   **시작하기** → 로그인 방법 **이메일/비밀번호** 사용 설정 → 저장. 이걸 하기 전에는 교사 계정을 만들 수 없다.
   (앱이 대신 시작하지 않는다. API로 시작하면 Identity Platform으로 올라가 요금 체계가 바뀔 수 있다.)
4. 노란 **"교사 로그인(이메일/비밀번호)이 꺼져 있습니다"**가 보이면 **지금 켜기**. 실패하면 옆 링크로 Firebase 콘솔에 가서 이메일/비밀번호를 켠다.
5. 빨간 **"Firebase 프로젝트가 서로 다릅니다"**가 보이면 1-2의 키를 1-1 프로젝트의 것으로 다시 받는다.
6. **설정** 탭에서 관리자 비밀번호를 새로 바꾼다. 이후 `ADMIN_PASSWORD` 값으로는 들어올 수 없다.
   잊으면 Firebase 콘솔 Firestore에서 `admin_config/console` 문서를 지우고 `ADMIN_PASSWORD`로 다시 들어온다.

### 1-6. (권장) Firestore 보안 규칙 배포
- 앱은 서버에서만 Firestore를 쓰므로 규칙이 없어도 동작하지만, 콘솔 규칙이 열려 있으면 누구나 자료를 읽을 수 있다.
- Firebase 콘솔 → Firestore Database → **규칙** 탭 → 저장소의 `firestore.rules` 내용을 붙여 넣고 **게시**.

## 2. 일반 수업 — 지금 바로 가능

| 언제 | 어디서 | 할 일 |
|---|---|---|
| 수업 전 | `/admin` → 수업 운영 | **새 반 만들기**(반 이름·입장 비밀번호). 수업 번호 여섯 자리가 나온다 |
| 수업 전 | `/admin` → 교사 계정 | 담임 계정(이메일·처음 비밀번호) 만들고 그 반 체크 |
| 수업 시작 | `/admin` → 수업 운영 | **수업 시작** → 칠판에 수업 번호·비밀번호. 1~6단계가 모두 열린다(단계를 따로 열지 않는다) |
| 수업 중 | 학생 | 첫 화면에서 수업 번호·비밀번호·자기 번호로 입장 → 아직 안 낸 가장 앞 문항부터 순서대로. 앞 문항을 내야 다음 문항이 보인다 |
| 수업 중 | 교사 `/teacher` | **학생 현황** 탭에서 번호별 진행·점수·답안 확인 |
| 다음 시간 | 학생 | 같은 번호로 다시 들어오면 이어서 푼다(번호로 이어진다) |
| 다 끝나면 | `/admin` → 수업 운영 | **수업 끝내기**(들어와 있는 학생도 내보내기 체크). 기록은 지워지지 않고, 다시 시작하면 이어서 푼다 |

일반 수업 점수는 공통 루브릭만으로 채점되며 **연구 자료가 아니다.**

## 3. 문항별 힌트 검수 (연구 전에)

힌트는 **목표(공통 한 문장 + 단계별 둘째 문장) + 확인 질문**(대상·특징·관계, 그 단계의 초점 영역이 맨 앞)으로 규칙에 따라
자동으로 만들어진다. 정답 값(대상 이름·색 이름·개수)이나 특정 부위는 말하지 않는다(36문항 전부를 시험이 확인한다).

- 관계 질문은 문항에 따라 다르다: A밴드 "서로 어디에 있는지(위·아래·옆·안)", 행동이 없는 사물·풍경(L22·L24·L25·L28·L30)
  "무엇이 어디에 어떻게 놓여 있는지", 그 밖의 B·C밴드 "어디에서 무엇을 하고 있는지".
- 관계가 기본으로 해당 없음인 문항(L01–L04·L06·L08·L11·L20·L23)은 학생 화면에서 관계 질문이 빠진다. 단서 팩이 있으면 단서 팩이 우선한다.

1. `docs/practice-hints-review.md`를 열어 36개 힌트를 읽는다(맨 위에 승인 방법이 있다).
2. **승인할 문항 ID**를 `src/lib/practice-hints.ts`의 `REVIEWED_QUESTIONS`에 넣고 `npm run hints:table` → `npm test` → 배포.
   승인 전에는 학생에게 단계 공통 안내가 그대로 나간다.
3. 36개를 모두 켠 모습은 미리 보기 브랜치(`hints-preview-all36`)의 Vercel 미리 보기에서 본다. 그 브랜치는 `main`에 합치지 않는다.

## 4. 연구 수집(v12)을 시작하려면

연구 수업 반은 아래 네 가지가 갖춰져야 만들 수 있다(`registry.readiness()`). 사전·사후 검사(T1~T3) 조건은 v12에서 뺐다.

1. **단서 팩 올리기** — 연구자가 v12-2 형식(coreObjects·requiredAttributes·requiredContext·acceptedExpressions·notRequired·
   contradictions·anchors 1~4)으로 만든 `cue-pack.json`을 `/admin` → **연구 자료** 탭 맨 위 **단서 팩** 영역에서 고른다.
   먼저 형식을 확인해 L01~L36마다 적재/실격(까닭)/없음을 보여 주고, **저장**을 눌러야 Firestore 관리자 전용 문서
   (`admin_config/cue_pack`, 클라이언트 읽기·쓰기 금지)에 들어간다. 내용은 화면에 다시 보이지 않는다.
   - 36문항이 모두 적재되어야 연구 반을 만들 수 있다. `cueVersion`은 올릴 때마다 새 이름으로 바꾼다(같은 이름에 다른 내용은 거부).
   - 연구 수업 중에는 팩을 바꾸지 않는다(서버마다 최대 60초 늦게 반영된다).
2. **환경 변수(값은 운영자만 안다)** — `CONSENT_VERSION`(동의서 버전), `IRB_APPROVAL`(승인 번호),
   `EVALUATION_MODEL_VERIFIED=true`(모델 접근·출력 확인 뒤), `PARTICIPANT_CODE_PEPPER`(긴 난수, 참가 번호 발급에 필요).
3. **연구 수업 반 만들기 → 참가 번호 발급** — 반 카드의 **참가자·동의**에서 인원수만큼 참가 번호를 한 번에 발급하고 바로 인쇄한다
   (번호는 다시 볼 수 없다. 이름 칸 없음 — 실명 대응표는 앱 밖에서 관리). 종이 동의서를 확인한 뒤 학생마다 **보호자 동의**·**학생 승낙**을 체크한다.
   둘 다 있어야 연구 기록이 모이고 추출에 들어간다. **철회**는 되돌릴 수 없으며 기록을 지우지 않고 이후 수집·추출에서 뺀다.
4. **실제 모델 예비 점검** — 수집 전에 연구자가 구성한 문장(대표 사진 3장 × 8개 = 24개)을 운영 채점기로 돌려 결측률·fallback률을 본다.
   ```bash
   GOOGLE_GENAI_API_KEY=… node --import tsx --import ./scripts/_node-server-modules.mjs scripts/pilot-score.mjs --input 문장.json
   ```
   입력: `[{"questionId":"L05","text":"…"}, …]`. 결과는 `rp_pilot_<시각>.csv`(로컬 파일)와 화면 요약뿐이며 연구 저장소에 쓰지 않는다.
   단서 팩 파일이 로컬에 있어야 연구 수업과 같은 경로로 채점된다(`RESEARCH_ASSET_DIR`). 없으면 `--experience`로 공통 문언만 쓴다.

앱 종합 수준 규칙: 해당 영역 수준 평균(해당 없음 제외)을 반올림(0.5 올림, 예: 2.5 → 3)한 1~4.

## 5. 연구 자료 추출 (자료가 모인 뒤)

1. `/admin` → **연구 자료** 탭. 동의가 지금 유효한 학생만 집계된다(철회자는 자동으로 빠진다).
   예전(v7, 100점) 방식으로 채점된 기록은 요약·추출에서 빠지고 몇 건이 빠졌는지 표시된다(연구자용 시도별 CSV에만 옛 값이 남는다).
   개인정보 점검으로 멈춘 제출 수도 건수로 보인다(글은 남기지 않는다).
2. 필요하면 **시도별 CSV / 학생×문항 요약 CSV / 문항 요약 CSV**를 받는다.
3. 문항 요약 표에서 A·B·C 대표 문항을 하나씩(모두 셋) **고르기** → **후보 불러오기**. 대표 사진을 정해 설정값
   `RESEARCH_SAMPLE_QUESTIONS`(예: `L05,L16,L31`)에 넣으면 미리 골라져 있다. 밴드가 겹치면 경고가 뜬다(막지는 않는다).
4. 행을 눌러 첫·최종 프롬프트와 피드백을 보고, 부적절하면 **제외**(무관한 내용 / 개인정보 포함)와 메모를 단다.
   '개인정보 의심' 표시는 참고용이며 자동으로 빼지 않는다.
5. 수준마다 뽑을 수(기본 5)와 **시드**를 확인하고 **추출하고 CSV 세 개 받기**. 3문항 × 앱 종합 4수준 × 5 = 60건.
   - **전문가용**(`…_expert.csv`): 새 사례번호(E001…)·사진 ID·학생 문장만. 앱 판정이 없으므로 이 파일만 전문가에게 준다.
   - **연구자용**(`…_researcher.csv`): 새 사례번호와 앱 사례 ID의 대응표 + 앱 판정.
   - **뺀 수**(`…_exclusions.csv`): 문항 × 사유(무관한 내용·개인정보·동의 없음·최종 결측)별 수.
   - 같은 시드·같은 후보면 같은 결과(같은 새 사례번호)가 나온다. 시드는 논문에 기록한다.
   - 후보가 모자란 층은 있는 만큼만 뽑힌다(표에 −n으로 표시, 다른 층에서 채우지 않고 부족분으로 보고).
6. **반복 채점**: 지난 추출 줄의 **2회차**·**3회차** 단추를 누르면 60건을 운영 채점기와 같은 설정으로 다시 채점해 따로 저장한다
   (1회차 = 학생이 냈을 때의 채점은 그대로). 끝나면 **회차별**·**일치 비율** CSV를 받는다. 모델 키가 있어야 하고 시간이 걸린다.
7. 받은 CSV는 컴퓨터에만 보관한다. **저장소(GitHub)에 올리지 않는다.** 지난 추출은 같은 탭 아래에서 다시 받을 수 있다.
